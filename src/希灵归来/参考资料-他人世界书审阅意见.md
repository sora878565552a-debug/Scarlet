# 参考世界书审阅意见（他人制作，未采用）

审阅对象：`希靈帝國 (1).json`，263 条、约 86 万字。顶层为 SillyTavern 世界书导出（`entries` + `originalData`），非角色卡。

## 一、它是什么

| 类别 | 数量 | 说明 |
|---|---|---|
| 「第 N 章」剧情摘要 | 约 170 条 | key 为章号，单条约 3000-4700 字，属剧情梗概而非设定 |
| 人物条目 | 约 80 条 | 陈俊、珊多拉、潘多拉、希尔维亚、冰蒂斯、星臣、希拉、哈兰、奥卡姆等原作人物 |
| 设定条目 | 4 条蓝灯 + 数条绿灯 | `世界观与核心设定`、`新希灵帝国主要机构设定`、`希灵帝国整體`、`叙事真实感`、`希灵舰船科技清单` |

它是**《希灵帝国》原作向的综合性世界书**，服务对象是「以陈俊为主角、在原作时间线上跑剧情」的卡，与我们的卡（玩家是旧帝国第三天区的皇帝）**不是同一条时间线**。

## 二、重要判断：人物条目大量属于二次创作

不能直接当原作事实使用。两个明确证据：

- `渡鸦` 条目给她起名「莫莉（Molly）」、编号 RVN-001，并编入「星环之围」战役、「奥术黑客」能力、与维嘉 73% 模拟胜率等成就与台词。这些**不见于原作**。
- `希尔维亚` 条目写她「在旧帝国末期被叛徒扎卡姆暗算并推入虚空」。而原作中把她带回的是陈俊，设计她的是**奥卡姆**（旧帝国首席科学家）。名字对不上，属杜撰或错记。

同类风险遍布那 80 条人物条目：它们读起来像设定，实际是「原作事实 + 作者扩写」的混合物。我方的 `世界总纲`、`主要种族`、`帝国历史` 等条目以**已查证的百度百科与光明网资料**为准，不采用这些扩写。

另需注意与已确认设定冲突之处：该文件写希尔维亚「被陈俊寻获并带回」发生在旧帝国末期，而本卡时间线中陈俊成皇是**大灾难之后**的事。它把两段时间压扁了。

## 三、可以直接用的部分（建议采纳）

### 1. `希灵舰船科技清单` —— 最有价值的一条

它比我们自己的 `舰船分级` 更严谨：明确区分「原作明确」与「战术推断」，并为每条舰写出**弱点**与战术定位。还额外提供三类我们完全没有的载具：

- 小型载具：**盲目者级**（侦察/骚扰/小规模运兵，五人以下，机动强、武装一般）、**狂热者级**（三人高机动突击载具，矢量粒子炮，装甲脆弱）、**争斗者级**（约载五十人，小型载具中装甲较厚、配相位护盾，但火力薄弱）。
- 同时它补齐了永恒级的细节：实体装甲与多种能量护盾**相互嵌套**、设异空间能量反应炉、极端情况最低操作人员为零。
- 补出荣耀级的一条限制：**具现过程极难，即使是潘多拉也需要约一个月**。

对本次审阅的意义：**这正好补上我们卡的一个空洞**——主角那艘「小型飞船」一直没定舰体归属，而小型载具的名称与定位现在有了候选。不过这三条小型载具我未能在公开资料中核实到出处，采用前需注明「来源为他人世界书，未核实」。

### 2. `叙事真实感` —— 最有价值的一条规则，且是我们缺的那一层

这是一份 **D0 级创作规则**，主题是「角色的认知必须受其时空背景与个体局限约束」。它的两条原则很实用：

- **信息视界原则**：角色只能知道自己通过经历、感官、交流获得的信息，知识是动态增长的过程，不是静态数据库。对陌生人只能依据外貌、衣着、言行作初步判断，**禁止直接识别隐藏身份**。
- **人性化智识原则**：智力型角色的智慧要通过洞察、联想、推理体现，而不是罗列数据和分析步骤；决策要受情感与经历影响，允许非最优选择。

**这条对我们卡的价值极高**：我们正需要防止 AI 让薇洛拉无所不知、或让路人一眼看穿玩家的皇帝身份。这应该成为我们 `创作规则` 条目的第一批内容。

### 3. 条目写法参考

人物条目的字段结构（name / alias / appearance / personality / background / dialogue_examples / special_abilities / relationships）组织清晰，可作为我们将来写大量 NPC 时的格式参考；`对话示例` 一栏对稳定人物语气尤其有效。

## 四、不建议采用的部分

- **约 170 条章节剧情摘要**：与我们的卡无关，且体量巨大，一旦导入会持续争抢上下文。
- **约 80 条人物条目**：其中大量扩写与杜撰，且多数人物属于「新帝国时代」，与玩家所处的旧帝国时间线不符。若将来某个原作人物要在我们卡里登场，应当针对该人物单独查证后另写条目，不使用这些。
- **它的整体架构**：全部 263 条 order 都是 100，没有分层；包含 11 条内容为空但已启用的条目；`希灵帝国整體` 设为蓝灯却带关键词。

## 五、配置层面的问题（我们不要照抄）

1. **没有顺序分层**：order 全为 100，意味着一旦多条同时触发，插入顺序不可控。我们的分层（骨架 1-6、详情 50-58、产业线 60）应当保留。
2. **空条目已启用**：11 条零字数条目仍然开启，属无效配置，应清理或禁用。
3. **蓝灯条目带关键词**：蓝灯不需要关键词，带了会让维护者误判其触发方式。
4. **旧式 `key` 数组**：该文件用英文 `key`，我们的本地文件用中文 `关键字`，后者是工坊 `tavern_sync` 的字段名，不可混用。

## 六、结论与建议动作

| 建议 | 内容 | 优先级 |
|---|---|---|
| 采纳 | 把 `叙事真实感` 的两条原则吸收进我们的 `创作规则`（D0），改写为适配本卡主体（薇洛拉的认知边界、身份不可被直接识破） | 高 |
| 采纳 | 用 `希灵舰船科技清单` 校对并补充我们的 `舰船分级`：补齐永恒级防护细节、荣耀级具现耗时，并考虑加入三种小型载具（标注来源未核实） | 中 |
| 参考 | 用它的 `对话示例` 写法加固薇洛拉的语气稳定性 | 低 |
| 不采纳 | 263 条中的章节摘要与人物条目；不导入其配置 | — |
